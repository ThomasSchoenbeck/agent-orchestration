# Tasks — 2026-06-12: Reviewer owns review + merge (auto-PR, AI conflict resolution)

Progress markers: `[x]` done · `[]` pending · `[~]` in progress

## Target lifecycle (confirmed)

1. Worker pushes the feature branch → **AWAITING_REVIEW**.
2. **1st review** — a reviewer agent claims it (→ REVIEWING) and reviews the code. Approve →
   **AWAITING_MERGE**; changes requested → **AWAITING_REVISION**. (No PR yet.)
3. **2nd review / merge phase** — a reviewer (via `handles_merge`) or a human **picks up** the
   `AWAITING_MERGE` task. A **PR opens at that point** (feature → main). The agent **merges main into
   the feature branch** and **resolves conflicts with the LLM** (reads conflicted files, edits, commits,
   pushes); if it can't → **AWAITING_REVISION** with **agent comments**. If clean and the merge
   completes → **COMPLETED**.

Decisions: conflict fixing = **agent resolves with AI**; the PR opens **when the merge phase is
picked up** (a task in `AWAITING_MERGE` claimed into `MERGING`), or via the human **Create PR**
button. Reviewer role carries **`handles_review` + `handles_merge`** (owns both phases); deployer =
`handles_deploy` only.

## Honest scope notes / risks

- **Reviewers become code-editing agents.** They already clone the feature branch, and the
  worker path already has commit+push — so the plumbing exists, but reviewers gaining
  merge/resolve/push is a real behavior change to validate carefully.
- **Phase C is the hard, open-ended part** (LLM conflict resolution quality, loops, push races).
  Phases A–B + D deliver a coherent, testable workflow on their own (auto-PR, branch update, conflict
  detection → revision with comments, reviewer-owned merge); C layers the AI fixing on top.
- **Existing-DB capability:** adding `handles_merge` to the seeded reviewer role only affects fresh
  DBs; existing reviewer roles need the capability toggled in Settings (Roles page) or a small
  migration. Flag if you want an automatic backfill.

## Suggested order

Do **Phase A** first (clear, low-risk, immediately useful), then **B** and **D** (mechanical, fully
testable), then **C** (the AI resolution) once the surrounding workflow is solid.
