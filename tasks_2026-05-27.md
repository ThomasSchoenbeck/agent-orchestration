## Task 5 — Agent: structured stdout logging

**Goal:** Agents write structured, human-readable log lines to stdout for every observable action: polling, task pickup, LLM calls, tool calls (with file paths / commit SHAs), and errors. Important events are also forwarded to the server via `PostLog` so they appear in the UI log viewer.

### Current gaps
- Both `agent.go` and `executor.go` use bare `log.Printf` with inconsistent format and no structured fields
- `client.PostLog()` is called in only 2 of ~20 log sites (panics + task failure)
- Missing entirely: polling, task found/claimed, LLM request/response, tool arguments, file write/create, commit success
- Tools (`tools/code.go`, etc.) emit nothing

### What to do

**1. Add `AgentLogger` to the agent package (`agent/logger.go`)**

A lightweight logger wrapping an `io.Writer` (default `os.Stdout`):
- Format: `YYYY/MM/DD HH:MM:SS [LEVEL] agent=<name> task=<id> <message> [key=val ...]`
- Methods: `Info`, `Error`, `Debug` each accepting a message string + variadic `...Field`
- `WithTask(id)` / `WithAgent(name, id)` return scoped child loggers
- `PostLog` forwarding: `Info` and `Error` also call `client.PostLog()` when a client is set

**2. Wire `AgentLogger` into `Agent` and `Executor`**
- Add `log *AgentLogger` field to both structs
- Initialise in `Agent.Start()` after registration; pass scoped copy to `Executor`
- Replace all bare `log.Printf` calls with the structured logger

**3. Add the missing log points**

| Location | Event | Level | PostLog? |
|---|---|---|---|
| `agent.go pollLoop` | polling for task | debug | no |
| `agent.go pollLoop` | task found (id, type, role) | info | no |
| `agent.go pollLoop` | task claimed | info | yes |
| `agent.go pollLoop` | claim error | error | yes |
| `executor.go Run` | task started | info | yes |
| `executor.go execute` | LLM request (round, model) | info | no |
| `executor.go execute` | LLM response (tokens, stop_reason) | info | no |
| `executor.go execute` | tool call (name + key args) | info | yes |
| `executor.go execute` | tool result (name, ok/error) | info | yes |
| `executor.go commitTaskWork` | commit success (sha[:12], branch, message) | info | yes |
| `executor.go Run` | task done (status, tokens, duration) | info | yes |
| all existing error sites | upgrade to structured + PostLog | error | yes |

**4. Log key args for important tools**

In `tools/executor.go` (or each tool), emit at least:
- `write_file`: `path=<path> bytes=<n>`
- `read_file`: `path=<path>`
- `run_tests`: `dir=<dir>`
- `git commit`: `sha=<sha> branch=<branch>`

Pass logger via context key or as a field on the `tools.Registry`.

### Tests
- Unit: `AgentLogger` writes structured lines to a `bytes.Buffer`; `WithTask` scopes the task field correctly
- Unit: `Info` and `Error` calls invoke `PostLog` on the mock client; `Debug` does not
- Unit: `executor.Run` with a mock tool registry emits at minimum: task-started, tool-call, task-done log lines (captured via injected writer)
- Unit: `commitTaskWork` emits a commit log line with SHA and branch when the commit succeeds; emits error when it fails
- Integration: run a task end-to-end against a test server and assert stdout lines contain expected fields (task_id, tool name, commit sha)

### Files
- `agent/logger.go` (new)
- `agent/logger_test.go` (new)
- `agent/agent.go`
- `agent/executor.go`
- `agent/executor_test.go`

## Task 8 — Agent detail page

**Goal:** Clicking an agent opens a dedicated detail page (`#/agents/:id`) showing identity, every task worked on, full activity log, and a statistics panel.

### Current state
- `GET /api/agents/:id` returns the agent record only (name, status, roles, registered_at, last_heartbeat)
- `GET /api/tasks?agent_id=:id` and `GET /api/agent-logs?agent_id=:id` already work
- No aggregation/stats endpoint exists
- `App.svelte` renders `<Agents>` for all `#/agents` routes — no detail route

### What to do

**Backend — new `GET /api/agents/:id/stats` endpoint**

Returns:

```json
{
  "uptime_seconds":       86400,
  "status":               "busy",
  "tasks_total":          42,
  "tasks_completed":      38,
  "tasks_failed":         3,
  "tasks_in_progress":    1,
  "success_rate":         0.93,
  "avg_task_duration_ms": 14200,
  "total_tokens":         1820000,
  "input_tokens":         1200000,
  "output_tokens":        620000,
  "llm_calls":            187,
  "tool_calls":           543,
  "tool_errors":          4,
  "executions_started":   42,
  "executions_completed": 38,
  "executions_failed":    3
}
```

Sources:
- `uptime_seconds` — `NOW() - agents.registered_at`
- `tasks_*` — `SELECT status, COUNT(*) FROM tasks WHERE assigned_agent_id=? GROUP BY status`
- `avg_task_duration_ms` — `AVG(CAST((julianday(completed_at) - julianday(started_at)) * 86400000 AS INTEGER)) WHERE status='COMPLETED'`
- `total/input/output_tokens`, `llm_calls` — `SELECT SUM(...), COUNT(*) FROM metrics WHERE agent_id=?`
- `tool_calls` / `tool_errors` / `executions_*` — `COUNT(*) FROM agent_logs WHERE agent_id=? AND event_type=?`

**Frontend — routing**
- Add `{:else if $router.page === 'agents' && $router.params.length > 0}` branch in `App.svelte`
- Make agent cards in `Agents.svelte` link to `router.push('agents', a.id)` instead of toggling the log filter

**Frontend — `AgentDetail.svelte` (new page)**

1. **Header** — name, status dot, roles chips, mode badge, last-seen timestamp, back link
2. **Stats grid** — uptime ("2d 3h"), status, tasks total/completed/failed/in-progress, success rate %, avg task duration, total tokens ("1.82 M"), LLM calls, tool calls, tool errors
3. **Tasks table** — Title | Type | Role | Status pill | Started | Duration; row click → `#/tasks/:id`
4. **Activity log** — timeline chart + log table pre-filtered to this agent (reuse pattern from `Agents.svelte`)

Auto-refresh every 5 s.

### Tests
- Unit (Go): stats endpoint returns correct counts for seeded DB; zero-task agent returns zeros without divide-by-zero
- Unit (vitest): stats grid renders all stat cards; uptime formats correctly ("2d 3h", "45 m", "30 s")
- E2E (Playwright): agent card click navigates to detail; stats grid visible; tasks table lists agent's tasks; task row navigates to task detail; log filtered to that agent
