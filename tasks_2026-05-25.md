## Task 1: Provider role preferences + fix reviewer "no provider" error

`[x]` **Status:** done

### Root causes

Two problems contribute to this:

**A)** `buildAgent` in `main.go` creates the router with `router.New(cfg, llmReg)` but never
calls `rtr.LoadFromDB(database)`. DB-backed `RoleDefinition` records (which map role →
provider) are therefore ignored in agent mode. The router falls back to `cfg.Roles[role]`.
If "reviewer" is not in the config's `roles:` section, `RouteByRole("reviewer")` returns an
error → `CanExecute` returns false → "no provider available for roles [reviewer]".

**B)** Even if LoadFromDB were called, a role only works if there is an explicit
`RoleDefinition` row in the DB pointing to a provider. There is no fallback that lets any
available provider handle an unrecognised role. The user wants to be able to say "this
provider handles roles X, Y" directly on the provider, instead of having to create a
`RoleDefinition` per role.

### Changes

1. **`db/models.go`** — add `Roles []string` field to `Provider`.
2. **`db/migrations.go`** — add migration: `ALTER TABLE providers ADD COLUMN roles TEXT NOT NULL DEFAULT '[]'`.
3. **`db/providers.go`** — update `scanProvider`/`scanProviders`, `CreateProvider`, `UpdateProvider` to persist/read the `roles` column.
4. **`api/types.go`** — add `Roles []string` to `CreateProviderRequest` and `UpdateProviderRequest` (and to the response shape if needed).
5. **`server/handlers.go`** — map `req.Roles` into the provider struct in the create/update provider handlers.
6. **`llm/registry.go`** — add `roles map[string]string` (role → provider name) and methods `SetRoles(name string, roles []string)` and `GetForRole(role string) (LLMProvider, error)`. Populate in `Set` / `Remove`.
7. **`router/router.go`** — in `RouteByRole`, add a final fallback after the config lookup fails: call `r.registry.GetForRole(role)`. Use that provider with no model override and no system prompt (raw fallback).
8. **`main.go`** — in `buildAgent`, after `router.New(cfg, llmReg)`, call `rtr.LoadFromDB(database)` so DB role definitions are active in agent mode. Also, when loading DB providers in `buildAgent`, call `llmReg.SetRoles(p.Name, p.Roles)` so the registry's role index is populated.

## Task 2: Fix agents showing as offline after clean shutdown

`[x]` **Status:** done

### Root cause

Agents do not notify the server when they shut down. After a clean `Ctrl-C`:

- Agent records remain in the DB with status `idle` or `online` and a heartbeat
  timestamp from before shutdown.
- On next server restart the maintenance loop (`runMaintenance`, fires every 15 s)
  marks agents offline if `now − last_heartbeat > HeartbeatIntervalSec × 3`.
- Agents start up and use exponential backoff before registering. There is a race
  window where the maintenance tick fires before agents re-register, leaving them
  visibly "offline" in the UI.
- The two non-reviewer agents likely lost the race; the reviewer registered in time
  but then hit the "no provider" error (Task 1).

### Changes

1. **`server/handlers.go`** — add `POST /api/agents/{id}/offline` sub-route inside
   `handleAgentDetail`. Sets `agent.Status = "offline"` and calls `UpdateAgent`.
2. **`agent/client.go`** — add `SetOffline(ctx context.Context, agentID string) error`
   that POSTs to `/api/agents/{id}/offline`.
3. **`agent/agent.go`** — add `Deregister(ctx context.Context)` that calls
   `a.client.SetOffline(ctx, a.id)` (no-op if `a.id == ""`).
4. **`main.go`** — in `runAgents` shutdown goroutine and in `runAgent` after `<-ctx.Done()`,
   call `a.Deregister(context.Background())` before `a.Stop()` so the server marks the
   agent offline synchronously before the process exits.

### Files touched
- `server/handlers.go`
- `agent/client.go`
- `agent/agent.go`
- `main.go`

### Tests
- `server/lifecycle_test.go` (or new `agent_offline_test.go`) — register an agent, call
  `POST /api/agents/{id}/offline`, verify status is "offline" in DB.

## Task 3: Improve task update diff logging

`[x]` **Status:** done

### Root cause

`db.UpdateTask` logs `"Task updated"` with `old_status = ""` — the "from" state is
unknown because the function receives the already-mutated struct. Server handlers that
call `UpdateTask` don't emit any `log.Printf` describing what changed. Similarly,
`handleTaskComments` POST creates a comment with no server-side log output.

### Changes

**3a — Status changes (db layer)**

In `db/tasks.go` → `UpdateTask`:
- Before the `UPDATE`, `SELECT status FROM tasks WHERE id=?` to get `oldStatus`.
- If `oldStatus != t.Status`, pass `oldStatus → t.Status` into `logTaskEvent` and log
  with message `"Status changed: {old} → {new}"`.
- If status is unchanged, keep old_status and new_status equal and use message
  `"Task fields updated"`.

**3b — Description / payload changes (server layer)**

In `server/handlers.go` → `handleTaskDetail` PUT handler:
- After reading the old task but before applying `req.Payload`, capture
  `oldDesc` from `t.Payload["description"]`.
- After applying the update, if description changed, add `log.Printf("task %s: description updated", id)`.
- If status changed (from `req.Status`), add `log.Printf("task %s: status %s → %s", id, oldStatus, *req.Status)`.

**3c — Comment added (server layer)**

In `server/checklist_handler.go` → `handleTaskComments` POST case:
- After `CreateComment` succeeds, add `log.Printf("task %s: comment added (author_type=%s author_id=%s)", taskID, c.AuthorType, c.AuthorID)`.

## Task 4: Project file viewer, code editor, and diff view

`[x]` **Status:** done

### Overview

Add a **Files** tab to the Project Detail page that lets users:
- Browse the file tree of a project's git repo (any branch/ref)
- Open and edit files in a code editor
- Commit changes directly to the repo with a message
- View a unified diff of any file between two refs, or see all changed files
  between two branches

All reads and writes go through the project's server-managed bare git repo at
`{storage.root}/repos/{projectID}.git` using go-git. No working directory is
needed for reads or single-file commits — everything operates on the object store
directly.

---

### Backend

**4a — New `git/reader.go`**

Three functions operating on a bare repo:

- `ReadTree(repoPath, ref, subpath string) ([]TreeNode, error)` — returns
  the flat list of entries under `subpath` at `ref` (non-recursive; caller
  paginates by clicking into directories). Each `TreeNode` carries
  `{Name, Path, Type ("blob"|"tree"), Size, Mode}`.
- `ReadFile(repoPath, ref, filePath string) ([]byte, error)` — reads a blob
  by resolving `ref` → commit → tree → entry → blob.
- `ListBranches(repoPath string) ([]string, error)` — returns all branch refs
  so the UI can populate a branch selector.

**4b — New `git/writer.go`**

One function to commit a single file change without a working directory:

- `CommitFile(repoPath, branch, filePath string, content []byte, message, authorName, authorEmail string) (newSHA string, err error)`
  - Opens bare repo, resolves current HEAD of `branch`
  - Creates a new blob object for `content`
  - Rebuilds the tree, replacing/adding the entry for `filePath` (supports
    nested paths by walking sub-trees recursively)
  - Creates a new commit with the updated tree and current HEAD as parent
  - Advances the branch ref to the new commit SHA
  - Returns the new commit SHA

**4c — Diff additions in `git/diff.go`**

- `FileDiff(repoPath, baseRef, headRef, filePath string) (string, error)` —
  returns a unified diff string for a single file between two refs. Uses
  go-git's `object.Patch` on the two blob objects.
- `BranchDiff(repoPath, baseRef, headRef string) ([]FilePatch, error)` —
  returns all changed files plus their unified diffs between two refs.
  `FilePatch` carries `{Path, Status ("added"|"modified"|"deleted"), Diff string}`.

**4d — New API routes in `server/handlers.go`**

All mounted under `GET/PUT /api/projects/{id}/...`:

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/projects/{id}/branches` | List branches → `[]string` |
| `GET` | `/api/projects/{id}/tree?ref=main&path=` | Directory listing → `[]TreeNode` |
| `GET` | `/api/projects/{id}/file?ref=main&path=foo/bar.go` | File content → `{content: "…", encoding: "utf8"}` |
| `PUT` | `/api/projects/{id}/file` | Commit a file change → `{sha, path, branch}` |
| `GET` | `/api/projects/{id}/diff?base=main&head=feat&path=foo.go` | Single-file diff → `{diff: "…"}` |
| `GET` | `/api/projects/{id}/diff?base=main&head=feat` | All-file diff → `[]FilePatch` |

The `PUT /file` request body: `{path, content, branch, message, author_name, author_email}`.
`author_name` and `author_email` default to `"user"` / `"user@localhost"` when omitted.

Binary files: detect with a null-byte check; return `{binary: true}` with no
content rather than base64-encoding.

Error cases: ref not found → 404; binary file in editor → 422 with `binary:true`;
empty repo (no commits yet) → empty tree `[]`.
