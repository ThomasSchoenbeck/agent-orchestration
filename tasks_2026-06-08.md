### Design changes during implementation

- **"Task type" → `agent_role`.** `tasks.type` was retired (Feature 3). The metrics ledger already
  stores `agent_role`, so the task-type filter uses that — **no JOIN to `tasks` anywhere**.
- **No separate detail endpoint.** `CostBreakdown` gained `task` (`task_id`) and `chat`
  (`conversation_id`) group-by dimensions, so it covers per-agent/task/chat drill-down directly.
- **IDs as links, not joined labels.** `tasks` has no title column; the page links `agent_id` →
  `#/agents/{id}` and `task` → `#/tasks/{id}` instead of joining for names.

## Why

The Providers page (`ui/src/pages/Providers.svelte`) already shows a compact "Cost breakdown"
box (F6) backed by `GET /api/metrics/costs?group_by=…` → `db.CostBreakdown`. It supports a single
group-by dimension and **no filtering or date range**. The user wants a dedicated, linkable cost
detail page reached from that box, with drill-down per agent / per task / per chat and filters on
task type, model, date, and other dimensions.

## Current state (verified)

- **DB**: `db/logs.go` → `CostBreakdown(ctx, groupBy)` returns `[]*CostBucket{Key, InputTokens,
  OutputTokens, Cost, Count}`. Group-by whitelist `costBreakdownColumns`: `source`, `agent_role`,
  `agent_id`, `provider`(→`provider_id`), `model`, `project`(→`project_id`), `day`(→`date(created_at)`).
  Query has **no WHERE clause**.
- **metrics columns**: `id, task_id, agent_id, model, tokens_used, input_tokens, output_tokens,
  cost, duration_ms, success, created_at, source, provider_id, agent_role, conversation_id,
  project_id` (`db/migrations.go`). There is **no task-type column** — task type lives on
  `tasks.type`, so any task-type filter/grouping needs a `JOIN tasks ON metrics.task_id = tasks.id`.
- **Handler**: `server/llm_handler.go` → `handleMetricsCosts` (route `/api/metrics/costs`).
- **Frontend API**: `ui/src/lib/api.js` → `getCostBreakdown(groupBy)`, `getTaskCost(taskId)`.
- **Routing**: hash router in `ui/src/lib/stores.js` (`router.go(page)`, `router.push(...segments)`,
  `$router.page`, `$router.params`). Pages wired in `ui/src/App.svelte` via `{#if $router.page === …}`
  and listed in the `pages` nav array (line ~16). Pages use Svelte 5 runes (`$state`, `$derived`).
- **Existing tests**: `db/cost_breakdown_test.go`.

## Decisions (assumed — confirm if wrong)

- **Separate routed page**, not a modal. New page id `costs`, reached at `#/costs`. Keep the
  compact box on Providers as a summary; its heading becomes a link to `#/costs`. This matches the
  user's wording ("cost detail page as link to the cost box").
- **No new nav entry by default.** The page is reachable via the box link, not the left nav, to
  avoid scope creep. (Easy to add a nav item later if wanted — noted in T6.)
- **Filters supported**: date range (from/to), `model`, task type (`tasks.type`), `source`
  (agent vs chat), `provider`, `agent_role`. All optional, combinable, applied as a SQL WHERE.
- **Drill-down dimensions**: the page reuses the existing group-by dimensions plus a detail row
  list. "Per agent" = `agent_id`/`agent_role`, "per task" = `task_id`, "per chat" =
  `conversation_id`. These are existing columns; only task-type needs the JOIN.
- **Backward compatible**: the current `group_by`-only call keeps working; filters are added as
  extra optional query params so the existing Providers box is untouched behaviorally.

## T1 — Backend: filterable cost breakdown

**Goal:** `CostBreakdown` accepts an optional filter set and applies it as a WHERE clause; task-type
grouping/filtering joins `tasks`.

Outline:

- Add `CostFilter` struct in `db/logs.go`: `From, To *time.Time`, `Model, TaskType, Source,
  ProviderID, AgentRole string` (empty = ignored).
- Add `task_type` to `costBreakdownColumns` mapping to `tasks.type` and switch the query to
  `FROM metrics LEFT JOIN tasks ON metrics.task_id = tasks.id` **only when** task_type is used as
  group-by or filter (or always LEFT JOIN — simpler, measure perf). Prefer conditional join to keep
  the common path index-friendly.
- Build the WHERE from non-empty filter fields using bound `?` params (never string-interpolate
  values — keep the existing injection-safe pattern where only whitelisted *columns* are
  interpolated).
- New signature: `CostBreakdown(ctx, groupBy string, f CostFilter)`. Update the single existing
  caller in `server/llm_handler.go`. Keep `CostBucket` unchanged.

Files: `db/logs.go`, `server/llm_handler.go`.

Tests (T7): extend `db/cost_breakdown_test.go` — filter by model, by date range, by source; verify
task-type grouping via JOIN; verify empty filter == current behavior.
