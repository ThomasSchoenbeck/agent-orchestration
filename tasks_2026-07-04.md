# Tasks 2026-07-04 — Multi-Session Agent Orchestration

Feature: agents run a thin **main orchestration session** per task that maintains
durable task memory and **synchronously** delegates all real work to core
subagents — prompt preparation, code discovery, a role-specific **work** subagent
(coding / review / planning), and a **task_status** subagent that tracks progress
and prepares session hand-offs. When a session exhausts its context window it
transitions to a fresh session, reconstructing progress from the **task event log +
task status history** (with a worktree scratchpad), so even a *remote* agent
without worktree access can catch up and continue. Nothing agent-internal is ever
merged into the project repo.

### Clarifications incorporated (2026-07-04)
- Subagents run **synchronously**; the spawning session waits for results.
- The main session delegates work to **per-role work subagents**: `code_subtask`
  (worker) and `review_subtask` (reviewer). The **orchestrator/planner workflow is
  left unchanged** (inline planner tools, direct completion) — the new
  multi-session machinery applies to **worker + reviewer only**.
- **Role tool allowlist is repurposed to orchestration-only** (run_subagent,
  memory, checkpoint, request_input, task_comment, + planner tools). Work tools
  live on the work subagents. Layers are per-session, so neither supersedes the
  other. *(Confirm — see open question.)*
- **Prompt-prep** is a mandatory core subagent that composes **all layered system
  prompts (agent, role, subagent, provider, model) + the task description** into
  the prompt for a call, then on subsequent calls rolls forward using the **actual
  prompt used + the LLM's result**. It runs before **every LLM round** in the main
  session **and** in each work/discovery/task_status subagent session (never for
  itself).
- Core subagent skills are **mandatory**: a preflight fails the task fast if a
  required core skill is missing/disabled. No feature flags.
- **Config restructure**: models drop their `roles[]` and gain a model-level system
  prompt; **roles and subagent skills each carry an ordered provider>model priority
  list** with automatic **failover on error/unavailability only**. This removes all
  model↔role/subagent mapping complexity.
- **task_status** runs as a subagent (keeps the main session lean) with a
  **catch-up mode**: if the main session dies before a hand-off is prepared, a new
  main session spawns task_status to reconstruct progress from events/history/branch.

## Assumptions (challenge any that are wrong)

- The **main session is a thin orchestrator** (worker + reviewer tasks): its LLM
  rounds decide which subagent to call next (discovery → work → …) and when to
  finish/checkpoint; it does no file work itself. **Orchestrator/planner tasks keep
  their current path unchanged** (`IsPlannerTask`: inline planner tools, direct
  completion, no work subagent, not subject to the new preflight).
- **Routing**: task.Role → RoleDefinition's provider>model priority list → first
  available model (failover). Subagents resolve their own priority list. Agent
  definitions no longer bind a model — the role/subagent lists own that.
- **Failover triggers only on model errors/unavailability** (timeout, 5xx,
  connection refused, circuit-open); normal completions stay on the first model.
  Reuse existing `llm_resilience.go` / `circuit_breaker.go` / `retry.go`.
- **Prompt-prep swaps `messages[0]`** (system) each round and preserves the running
  history; roughly doubles LLM calls across main + subagent sessions (accepted:
  own LLMs, quality over cost).
- Memory scratchpad = worktree `.agent_context/` (gitignored, never committed);
  the **portable** source of truth for continuation/remote-recovery is task events
  + status history + branch contents.
- Sessions are logical (one executor process); subagent calls are synchronous
  goroutine-bounded loops, not a new process/queue tier.
